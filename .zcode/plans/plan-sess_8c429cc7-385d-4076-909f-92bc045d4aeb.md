# Plan: comando `add-candidate` (backfill de candidato)

**Respuesta corta:** sí, es viable. Se implementa el espejo exacto de `add-judge` (`addJudgesToRun`): copiar el run a un directorio derivado, añadir el modelo nuevo al manifiesto, ejecutar **solo los jobs del candidato nuevo** (casos × repeticiones) y hacer que **únicamente los jueces ya existentes del run** califiquen las salidas de ese candidato. Los candidatos existentes no se vuelven a llamar.

## 2. `addCandidatesToRun` — nuevo `src/candidates/backfill.ts`

Simétrico de `src/judges/backfill.ts:34-122` (mismos guards, mismo patrón copy-on-write):

1. `loadPersistedRun(sourceDirectory)`; recargar dataset desde `sourceRun.datasetPath` y verificar `dataset.length === datasetCaseCount`; `casesById`.
2. Dedupe contra `sourceRun.candidateModels` → `addedCandidates` / `skippedCandidates`; error si no queda nada nuevo ("ya participaron en esta ejecución").
3. Directorio derivado por defecto `` `${sourceDirectory}-addcandidate-${slugify(addedCandidates.join('+'))}` ``; error si ya existe.
4. `cp` recursivo → `RunStore.resume(directory)` → `store.addCandidateModels(addedCandidates, addedCandidates.length * dataset.length * sourceRun.repetitions)`.
5. Merge de pricing (catálogo fresco sobre el almacenado) y warning de `promptVersion` ≠ actual — reutilizados tal cual de judges/backfill.ts:69-86.
6. Construir jobs solo para los candidatos nuevos (modelo × caso × repetición `1..sourceRun.repetitions`) y ejecutar con `runWithConcurrency` el mismo pipeline de `runBenchmark` (runner.ts:82-98):
   - `runCandidateCase` (stages/candidate.ts:198) → `store.recordCandidateRun`
   - `judgeCandidateRun` con **`sourceRun.judgeModels`** (el panel completo existente) → `store.recordJudgeRecord` — así los jueces solo califican las salidas del modelo nuevo
   - `store.completeJob(model, caseId, repetition)` + log de progreso `[n/total]`
7. `loadPersistedRun(directory)` → `buildReport` → `renderMarkdownReport` → `store.finish` (el informe agrega automáticamente el candidato nuevo; `byJudge`, desacuerdo entre jueces y costes se recalculan solos).

Tipos `AddCandidatesOptions { candidateModels, outputDir?, concurrency? }` y `AddCandidatesResult { run, directory, reportPath, reportMarkdown, addedCandidates, skippedCandidates, candidateRunCount, judgeCallCount }`.

Nota: si el run origen se ejecutó sin jueces, el candidato nuevo simplemente no es evaluado (consistente con `--skip-judges`).
